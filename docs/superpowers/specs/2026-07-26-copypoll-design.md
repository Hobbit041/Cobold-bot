# /copypoll — копирование существующего опроса в текущую тему — дизайн

Дата: 2026-07-26

## Назначение

Админ уже создавал опросы и хочет переиспользовать структуру одного из
них (название + варианты ответа) в новом чате/теме — без ручного набора
title/options заново через `/newpoll`. Новая команда `/copypoll` копирует
только "тело" опроса; голоса, состояние announced/reminder исходного
опроса не переносятся — новый опрос стартует с чистого листа.

Команда работает только при запуске прямо в группе (в нужной теме);
из личных сообщений с ботом — отказ с пояснением, т.к. личка не даёт
указать целевой чат/тему для публикации.

## Выбор опроса для копирования

По аналогии с уже существующим `/editpoll`: команда показывает
пронумерованный список активных опросов (`status == "active"`) вида
`"1. Название (id=5)"`, админ отвечает номером. Список не фильтруется по
чату — можно скопировать опрос из любого чата/темы, где бот когда-либо
публиковал опросы, в текущую тему.

Рассмотренные и отклонённые варианты:
- `/copypoll <id>` одной командой — отклонён, т.к. id опроса нигде не
  показывается пользователю в обычном режиме, неудобно.
- Reply на сообщение опроса — отклонён, работает только если исходное
  сообщение доступно в этом же чате, не решает кейс "скопировать из
  другой темы/группы".

## Поток

1. `/copypoll`, запущенный не-админом → "Эта команда доступна только
   администратору." (как у `/newpoll`/`/editpoll`).
2. `/copypoll`, запущенный в личных сообщениях (`message.chat.type ==
   "private"`) → отказ: "Эта команда работает только в группе, в теме
   которую нужно скопировать опрос." Диалог не начинается.
3. `/copypoll` в группе: запрос активных опросов из БД. Если пусто →
   "Активных опросов нет." Иначе — нумерованный список, сохраняем в FSM
   `poll_ids`, `target_chat_id = message.chat.id`,
   `target_message_thread_id = message.message_thread_id`, состояние
   `CopyPollStates.waiting_poll_selection`.
4. Админ отвечает номером. Некорректный номер/не число → "Некорректный
   номер. Попробуйте снова." (как в `select_poll` из `admin_edit.py`).
5. По валидному номеру: берём исходный `Poll` и его не удалённые
   `Option` (`repo.get_poll_options` уже фильтрует `is_deleted`),
   создаём новый `Poll` через переиспользуемую функцию публикации
   (см. ниже) с `title=source.title`,
   `options=[(opt.text, opt.date) for opt in source_options]`,
   `chat_id=target_chat_id`, `message_thread_id=target_message_thread_id`.
6. Успех → "Опрос создан и опубликован!", состояние очищено. Ошибка
   отправки сообщения в чат → откат созданного `Poll` в БД, понятное
   сообщение об ошибке (как сейчас в `_create_and_publish_poll`).

Что **не** копируется: голоса (`Vote`), `ThresholdState.announced`,
`Reminder.sent` — новые `Option` создаются через `repo.create_poll`,
который всегда заводит свежие `ThresholdState(announced=False)` /
`Reminder(sent=False)` без голосов, так что это не требует отдельной
логики "не копировать" — просто следствие переиспользования
`create_poll`.

## Реализация

- `bot/handlers/admin_create.py`: `_create_and_publish_poll` перестаёт
  читать `title`/`options` из `state.get_data()` и принимает их
  параметрами (`title: str, options: list[tuple[str, dt.date | None]]`).
  Вызовы в `finish_options` и `receive_target_chat` обновляются —
  передают `data["title"]` и распарсенные `options` явно. Поведение и
  сигнатура для остального (chat_id, message_thread_id, откат при
  ошибке) не меняются. Функция теряет ведущее подчёркивание
  (`create_and_publish_poll`), чтобы быть импортируемой из
  `admin_copy.py`.
- Новый файл `bot/handlers/admin_copy.py`:
  - `CopyPollStates(StatesGroup)` с одним состоянием
    `waiting_poll_selection`.
  - `start_copy_poll` (хендлер `Command("copypoll")`): проверка админа,
    проверка chat.type != "private", запрос активных опросов, список,
    сохранение состояния — по образцу `start_edit_poll`.
  - `select_poll_to_copy`: парсинг номера, загрузка исходного опроса и
    его опций, вызов `create_and_publish_poll` из `admin_create.py`.
  - Использует `cleanup_and_answer` для всех ответов (единообразная
    очистка сообщений в группе + 5-минутный тайм-аут диалога — тот же
    механизм, что у `/newpoll`/`/editpoll`).
- `bot/main.py`: `dp.include_router(admin_copy.router)` — после
  `dialog_control.router` (по той же причине, что и
  `admin_create`/`admin_edit`: `dialog_control` должен успеть
  перехватить `/cancel` раньше catch-all хендлера состояния
  `waiting_poll_selection`).
- Схема БД не меняется.
