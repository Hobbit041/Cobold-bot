# Telegram-бот для голосования по датам — дизайн

Дата: 2026-07-24

## Назначение

Бот для организации игр/встреч: администратор создаёт опрос с вариантами дат,
публикует его в чат, участники голосуют (можно за несколько вариантов сразу).
Когда за вариант набирается 4 голоса, бот уведомляет администратора в чате.
Накануне подтверждённой даты бот присылает список участников с просьбой
подтвердить участие реакцией.

## Стек

- Python 3.12
- aiogram 3.x (long polling, без вебхука/SSL)
- SQLite + SQLAlchemy (async, `aiosqlite`)
- APScheduler с `SQLAlchemyJobStore` (переживает перезапуск бота) — для
  дебаунс-таймеров и ежедневной проверки напоминаний

## Права доступа

Только один администратор — фиксированный Telegram user id в конфиге бота.
Только он может создавать опросы и редактировать варианты. Голосовать может
любой участник целевого чата.

## Модель данных

- **Poll**: id, chat_id, message_id, title, status (`active`/`closed`), created_at
- **Option**: id, poll_id, text, date (обязательна), position, is_deleted
- **Vote**: option_id, user_id, username, first_name, voted_at
- **ThresholdState**: option_id, announced (bool) — было ли отправлено
  сообщение «набралось 4 голоса» для текущего цикла
- **Reminder**: option_id, sent (bool) — было ли отправлено напоминание
  «накануне игры»

Несколько опросов могут существовать одновременно (в разных чатах или в
одном — независимо друг от друга).

## Сценарии

### Создание опроса

1. Администратор пишет боту в личку `/newpoll`.
2. Бот запрашивает название опроса.
3. Бот запрашивает варианты по одному, в формате `Текст | ДД.ММ.ГГГГ`
   (год можно опустить — берётся текущий); администратор завершает ввод
   командой `/done`.
4. Бот запрашивает целевой чат (пересылкой сообщения из чата или id).
5. Бот публикует в чат сообщение с inline-кнопками — по одной на вариант
   (toggle голоса) — и подписывает текущее количество голосов у каждой
   кнопки (0 в момент публикации).

### Голосование

- Нажатие на кнопку варианта переключает голос пользователя за этот вариант
  (добавляет, если не было; убирает, если был).
- Один пользователь может голосовать за несколько вариантов одновременно.
- После каждого голоса/снятия голоса бот редактирует сообщение опроса в
  чате, обновляя счётчики у всех вариантов.

### Порог в 4 голоса (с дебаунсом 15 минут)

- Когда голосов за вариант становится ≥ 4, запускается (или
  перезапускается, если уже был) таймер на 15 минут от момента этого
  голоса.
- Если по истечении 15 минут вариант всё ещё имеет ≥ 4 голосов —
  бот отправляет в чат: `@администратор, за вариант "%вариант%"
  проголосовало 4 человека!` — и помечает `ThresholdState.announced = True`.
- Если до срабатывания таймера голос снимается и становится < 4 — таймер
  отменяется, сообщение не отправляется.
- Пока `announced = True`, повторные пересечения порога вверх-вниз выше 4 не
  порождают новых сообщений о достижении порога.

### Падение ниже 4 после объявления

- Если `announced = True` и число голосов становится < 4 — бот немедленно
  отправляет в чат: `За вариант "%вариант%" снова меньше 4х человек.
  Проголосуйте, а то игра отменится!`
- `ThresholdState.announced` сбрасывается в `False`. Следующее достижение
  4 голосов снова проходит через дебаунс-цикл и новое объявление.

### Редактирование варианта

Доступно только администратору, через диалог в личке с ботом
(`/editpoll`): выбор опроса → выбор варианта → выбор действия
(удалить / изменить текст / изменить дату).

- Бот применяет изменение к варианту, редактирует сообщение опроса в чате.
- Если у варианта на момент изменения были голоса — бот отдельным
  сообщением в чат упоминает всех проголосовавших по `@username` и
  описывает изменение, например: `@user1, @user2, вы проголосовали за
  вариант, но он изменился! В опрос внесены изменения: "%старый текст%" →
  "%новый текст%"`.
- При удалении варианта с голосами — та же нотификация; голоса по варианту
  аннулируются, `ThresholdState`/`Reminder` для него удаляются.
- Участники без username в уведомлении не упоминаются напрямую (упоминание
  только по `@username`, если он есть).

### Напоминание «накануне игры»

- Ежедневно в 19:00 (Europe/Moscow) APScheduler-джоба проверяет все
  варианты с `ThresholdState.announced = True`, чья дата — завтра, и
  `Reminder.sent = False`.
- Для каждого такого варианта бот отправляет в чат сообщение:
  ```
  Напоминаю, что завтра, %число%, состоится игра! Пожалуйста, подтвердите
  участие реакцией на это сообщение:
  @User1
  @User2
  ...
  ```
  (участники — все проголосовавшие за этот вариант; список формируется
  построчно).
- После отправки `Reminder.sent = True`, чтобы не отправить повторно.

## Обработка ошибок и краевые случаи

- Голос от пользователя без username — сохраняется по user_id, в счётчиках
  и напоминаниях просто не упоминается по `@username` (см. выше).
- Опрос в чате, где у бота нет прав редактировать сообщения — при ошибке
  редактирования (`message can't be edited`, чат забанил бота и т.п.) бот
  логирует ошибку и продолжает работу (счётчики в БД остаются верными,
  повторная попытка редактирования — на следующем голосе).
- Перезапуск бота — активные дебаунс-таймеры и ежедневная джоба напоминаний
  восстанавливаются из `SQLAlchemyJobStore`, не теряются.
- Попытка редактировать/создать опрос не от администратора — бот отвечает
  отказом, не выполняет действие.

## Хостинг

VPS + systemd: бот запускается как systemd-сервис (`ExecStart=python bot.py`,
`Restart=on-failure`), работает через long polling — не нужен домен или
SSL-сертификат. SQLite-файл и `jobs.sqlite` (job store APScheduler) хранятся
на диске VPS, бэкапится вместе с проектом.

## Тестирование

- Юнит-тесты бизнес-логики (подсчёт голосов, переходы `announced`,
  дебаунс-таймеры, генерация текста уведомлений) — с моками времени
  (`freezegun` или прямой контроль планировщика), без реального Telegram API.
- Ручное тестирование сценариев (создание/голосование/редактирование/
  напоминание) через тестового бота в отдельном тестовом чате перед
  переключением на боевой.
