# Персистентное хранилище на bothost.ru через DATA_DIR

Дата: 2026-07-29

## Проблема

При перезапуске/редеплое бота на bothost.ru теряются все опросы: бот
«забывает» о существующих голосованиях, а также о запланированных заданиях
(порогах, напоминаниях, таймаутах диалогов).

## Корень проблемы

Приложение уже использует SQLite:

- опросы — SQLAlchemy async, путь из `Config.db_path`;
- задания APScheduler — `SQLAlchemyJobStore`, путь из `Config.jobs_db_path`.

Модель bothost.ru (bind-mount): при каждом старте контейнера каталог `/app`
монтируется из Git-исходников, поэтому переживает рестарт **только отдельный
том `/app/data`**. Всё, что записано вне `/app/data`, теряется.

Хотя кастомный `Dockerfile` включён и содержит корректные
`ENV DB_PATH=/app/data/...`, переменные окружения, заданные в **панели**
bothost, инжектируются в контейнер при запуске и **перекрывают `ENV` из
образа**. В панели заданы относительные значения:

```
DB_PATH=poll_bot.sqlite3
JOBS_DB_PATH=jobs.sqlite3
DATA_DIR=/app/data
```

Итог: `bot/config.py` читает `DB_PATH`/`JOBS_DB_PATH` как относительные пути,
SQLite-файлы пишутся в рабочий каталог (`/app`), который перезаписывается при
рестарте → базы исчезают. Переменная `DATA_DIR` в панели задана, но **кодом не
используется** — персистентный том простаивает.

## Решение (вариант B): разрешать пути к БД относительно DATA_DIR

Приложение приводится к модели bothost: данные живут в `/app/data`. Пути к БД
разрешаются относительно `DATA_DIR`, что делает бота устойчивым к настройкам
панели и не ломает локальную/systemd-разработку.

### Правила резолвинга пути

Хелпер `_resolve(path: str, data_dir: str) -> str`:

- если `path` абсолютный (`os.path.isabs`) → вернуть как есть;
- иначе, если `data_dir` непустой → `os.path.join(data_dir, path)`;
- иначе → вернуть `path` без изменений.

Матрица поведения:

| `DATA_DIR`  | `DB_PATH`                    | Результат                     |
|-------------|------------------------------|-------------------------------|
| `/app/data` | `poll_bot.sqlite3`           | `/app/data/poll_bot.sqlite3`  |
| `/app/data` | `/app/data/poll_bot.sqlite3` | `/app/data/poll_bot.sqlite3`  |
| `` (пусто)  | `poll_bot.sqlite3`           | `poll_bot.sqlite3` (как было) |

То же применяется к `JOBS_DB_PATH`.

### Компоненты

1. **`bot/config.py`**
   - читать `DATA_DIR` (default `""`);
   - применить `_resolve` к `db_path` и `jobs_db_path`;
   - `Config` остаётся с уже-разрешёнными абсолютными (на bothost) путями —
     остальной код не меняется.

2. **Гарантия каталога (startup)**
   - в `bot/main.py` перед `init_db` создавать родительские каталоги обоих
     файлов БД: `os.makedirs(os.path.dirname(path), exist_ok=True)` для
     непустого dirname. Защищает от падения SQLite на отсутствующем `/app/data`
     (том должен существовать, но mkdir — дешёвая страховка).

3. **`Dockerfile`**
   - убрать вводящие в заблуждение `ENV DB_PATH` и `ENV JOBS_DB_PATH` (их всё
     равно перекрывает панель);
   - оставить `ENV DATA_DIR=/app/data` и `RUN mkdir -p /app/data`.

4. **`.env.example` / `README.md`**
   - задокументировать `DATA_DIR` и правило: относительные пути к БД
     разрешаются внутри `DATA_DIR`.

### Тесты (TDD, `tests/test_config.py`)

- относительный `DB_PATH` + непустой `DATA_DIR` → путь внутри `DATA_DIR`;
- абсолютный `DB_PATH` + непустой `DATA_DIR` → путь неизменен;
- относительный `DB_PATH` без `DATA_DIR` → путь неизменен (совместимость);
- то же для `JOBS_DB_PATH`.

## Что вне рамок

- **Миграция старых данных не нужна:** прежние базы жили в эфемерном каталоге и
  уже потеряны — восстанавливать/переносить нечего. После фикса сохраняется всё
  новое.
- Схема БД, модели, логика опросов/голосований/напоминаний не меняются.
- FSM-состояние диалогов (`MemoryStorage`) остаётся в памяти — вне рамок этой
  задачи.

## Развёртывание

После мержа: убедиться в панели bothost, что `DATA_DIR=/app/data` (уже задан),
и сделать редеплой. Относительные `DB_PATH`/`JOBS_DB_PATH` в панели можно
оставить как есть — теперь они корректно разрешаются в `/app/data`.
