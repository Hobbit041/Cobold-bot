# /mygames — отключение, и число игроков в /checkme — дизайн

Дата: 2026-08-22

## Назначение

Два независимых, но мелких изменения к уже реализованным `/checkme`/
`/mygames` (см. `2026-08-22-checkme-design.md` и
`2026-08-22-checkme-mygames-date-split-design.md`):

1. **Отключить `/mygames`.** При проектировании выяснилось, что опрос,
   удалённый через `/deletepoll`, стирает голоса из БД безвозвратно —
   значит `/mygames` в принципе не может показать историю по таким
   играм, только по тем, что ещё физически в базе. Раз архивации при
   удалении нет, а игроки такой функционал прямо не запрашивали —
   команда убирается из диспетчера, пока не появится реальный запрос.
   Реализация не удаляется — она уже написана и покрыта тестами,
   включение обратно в будущем должно стоить одну строку.
2. **`/checkme` показывает число записавшихся.** Формат строки списка
   меняется с `(Название чата)` на `(Название чата, N игрок(а/ов))`,
   с грамматически верным русским склонением слова «игрок» по числу N.

## Изменение 1: отключение `/mygames`

В `bot/handlers/checkme.py` убирается декоратор
`@router.message(Command("mygames"))` над `handle_mygames` — сама
функция, `_build_lines`, `_answer_with_lines` и текстовые хелперы
`formatting.mygames_header`/`formatting.mygames_empty_text` остаются
без изменений. Над функцией добавляется короткий комментарий,
объясняющий, что она сознательно не подключена к роутеру (не описывать
здесь — не обычный комментарий-описание, а пояснение непрозрачного
решения: почему рабочий код не используется).

Существующие тесты (`test_handle_mygames_*` в
`tests/test_handlers_checkme.py`) вызывают `handle_mygames` напрямую
как функцию, а не через диспетчер aiogram — отключение регистрации их
не затрагивает, они продолжают проверять, что реализация рабочая.
Никаких изменений в тестах для этого пункта не требуется.

## Изменение 2: число игроков в /checkme

### Склонение

Стандартный алгоритм русского склонения количественных числительных
при существительном (уже применяется во многих русскоязычных ботах):

```python
def _pluralize_players(count: int) -> str:
    if count % 10 == 1 and count % 100 != 11:
        return "игрок"
    if count % 10 in (2, 3, 4) and count % 100 not in (12, 13, 14):
        return "игрока"
    return "игроков"
```

Примеры: 1 → «игрок», 2 → «игрока», 5 → «игроков», 11 → «игроков»,
21 → «игрок», 25 → «игроков».

### `bot/formatting.py`

`record_line` получает новый параметр `vote_count: int` и вставляет
число со склонённым словом в скобки после названия чата:

```python
def record_line(
    index: int, option_text: str, option_date: dt.date, chat_title: str, vote_count: int, link: str
) -> str:
    label = f"{format_date_ru(option_date)}, {html.escape(option_text)}"
    players = f"{vote_count} {_pluralize_players(vote_count)}"
    return (
        f'{index}. <a href="{html.escape(link)}">{label}</a> '
        f"({html.escape(chat_title)}, {players})"
    )
```

`vote_count` — целое число, не пользовательский ввод, экранирование
не требуется.

### `bot/handlers/checkme.py`

`_build_lines` должен знать число голосов по каждому `option_id`.
Число голосов не входит в `repo.get_votes_by_user` — вместо
переписывания этого запроса под агрегат, число берётся тем же
приёмом, что уже использует `bot/handlers/voting.py`
(`counts = {opt.id: await repo.get_vote_count(session, opt.id) ...}`):
цикл по `repo.get_vote_count(session, option.id)`, пока сессия ещё
открыта, до закрытия `async with session_maker() as session:`.

Оба хендлера (`handle_checkme`, «спящий» `handle_mygames`) собирают
`vote_counts: dict[int, int]` сразу после `get_votes_by_user` и
передают его в `_build_lines`, которая подставляет
`vote_counts[option.id]` в `formatting.record_line(...)`.

## Тестирование

- `tests/test_formatting.py`: `_pluralize_players` — приватная
  функция (ведущее подчёркивание), как и уже существующая
  `_dated_label` в этом же файле — по принятой в проекте конвенции
  такие функции не тестируются напрямую отдельным импортом, а
  проверяются через публичную функцию, которая их вызывает. Поэтому
  склонение проверяется через `record_line` с разными `vote_count`
  (1, 2, 5, 11, 21 — по одному на каждую ветку правила, плюс 11/12 как
  проверка исключения из общего «2-4»/«5-20» правила).
  `test_record_line_escapes_and_links` обновляется под новую сигнатуру
  с `vote_count`.
- `tests/test_handlers_checkme.py`: во всех сохранившихся `/checkme`-
  тестах, где сейчас голосует только один пользователь (`user_id=1`),
  ожидаемый текст обновляется — добавляется `, 1 игрок` в скобки.
  Тесты `/mygames` (не зарегистрированные, но вызываемые напрямую)
  обновляются так же — они по-прежнему покрывают рабочую
  реализацию.
