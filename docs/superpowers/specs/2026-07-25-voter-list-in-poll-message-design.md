# Показ списка проголосовавших в сообщении опроса — дизайн

Дата: 2026-07-25

## Назначение

Изначальный запрос — отдельная кнопка «Посмотреть голоса/Скрыть голоса» с
кликабельным списком проголосовавших. В процессе обсуждения выяснилось
техническое ограничение: всплывающее окно Telegram (`callback.answer`)
поддерживает только простой текст без кликабельных упоминаний, а
редактирование общего сообщения опроса кнопкой видно всем в чате, а не
только нажавшему. Личные сообщения от бота нельзя гарантированно отправить
(бот не может писать первым пользователю, который ни разу не запускал
диалог с ботом).

По итогам обсуждения решили: кнопка не нужна. Список проголосовавших
показывается сразу в тексте сообщения опроса, под каждым вариантом —
всегда видим, обновляется вместе со счётчиком при каждом голосе/правке.
Упоминания с `@username` и так становятся кликабельными в обычном тексте
Telegram без специального parse_mode (уже используется в остальных частях
бота).

## Формат

```
📅 Игра в апреле

1. 24.07 (24 июля) — 2 🗳
   @alice, Bob
2. 25.07 (25 июля) — 0 🗳
```

Если у варианта нет голосов — строка со списком не добавляется (как у
варианта 2 выше). Список голосовавших через запятую, с отступом на
отдельной строке под основной строкой варианта. Упоминание — как и везде
в проекте: `@username`, если он есть, иначе просто имя (без активной
ссылки) — уже реализовано в `formatting.voter_mention`.

## Реализация

- `bot/formatting.py`: `format_option_line` получает новый необязательный
  параметр `voter_mentions: list[str] | None = None`. Если список непустой —
  добавляет вторую строку с отступом. Обратная совместимость: вызовы без
  этого параметра работают как раньше (пустой список вариантов без строки
  голосов — не должно случиться в реальности, т.к. все три места вызова
  теперь всегда передают голосующих, но сигнатура остаётся необязательной
  для устойчивости тестов и вызовов).
- Три места, где строится текст сообщения опроса — `bot/handlers/admin_create.py`
  (первая публикация), `bot/handlers/voting.py` (после голоса),
  `bot/handlers/admin_edit.py` (`_refresh_poll_message`, после правки/удаления) —
  обновляются: для каждого варианта дополнительно получают список голосов
  через `repo.get_voters` и передают собранные `voter_mention(...)` в
  `format_option_line`.
- Кнопки/callback_data/схема БД не меняются — фичи со скрытием/показом нет,
  список всегда виден.

## Тестирование

- Юнит-тесты `bot/formatting.py`: `format_option_line` с пустым и непустым
  `voter_mentions`.
- Обновление существующих тестов хендлеров (`test_handlers_admin_create`,
  `test_handlers_voting`, `test_handlers_admin_edit`), которые проверяют
  текст сообщения опроса — добавить голосующего и проверить, что его
  упоминание попадает в текст после голосования/публикации/правки.
