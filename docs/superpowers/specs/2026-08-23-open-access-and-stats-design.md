# Открытый доступ + /stats — дизайн

## Проблема

Бот сейчас разрешает создание/редактирование/удаление/копирование опросов и
`/cancel` только одному человеку — `ADMIN_ID` из `.env`. Нужно снять это
ограничение и сделать бота пригодным для использования в любых группах, но
сохранить возможность разработчику (тому самому `ADMIN_ID`) через `/stats`
узнать, в скольких группах бот используется, с названиями групп и датой
последнего опроса в каждой.

## 1. Авторизация действий с опросами

Вместо сверки с единственным захардкоженным ID проверяем, что обратившийся —
админ/создатель **конкретного чата**, к которому относится действие. Способ
проверки такой же, как уже используется для кнопки удаления в `/checkme`:
`bot.get_chat_member(chat_id, user_id).status in ("administrator", "creator")`.

### Новый общий хелпер

`bot/authz.py`:

```python
async def is_chat_admin(bot: Bot, chat_id: int, user_id: int) -> bool:
    try:
        member = await bot.get_chat_member(chat_id, user_id)
    except Exception:
        return False
    return member.status in ("administrator", "creator")
```

Ошибка API (бот не в чате, чат недоступен и т.п.) трактуется как «прав нет»
(fail-closed). `bot/handlers/checkme.py::handle_delete_button` переводится на
этот хелпер вместо дублирующего инлайн-кода.

### Команда за командой

- **`/newpoll`** (`admin_create.py`): параметр `admin_id` и `_is_admin`
  убираются.
  - Если команда запущена прямо в группе/супергруппе — проверка
    `is_chat_admin(bot, message.chat.id, user.id)` выполняется сразу в
    `start_create_poll`; при отказе — то же поведение, что и раньше
    (`cleanup_and_finish` с текстом отказа), просто без сверки с фиксированным ID.
  - Если команда запущена в личке с ботом — целевой чат ещё не известен,
    проверка originally недоступна. Она переносится в `receive_target_chat`,
    сразу после того как `chat_id` резолвится (пересланное сообщение или
    введённый id), и выполняется **до** вызова `create_and_publish_poll`.
    При отказе — `cleanup_and_finish` с текстом отказа, опрос не создаётся.
- **`/editpoll`, `/deletepoll`** (`admin_edit.py`, `admin_delete.py`):
  параметр `admin_id`/`_is_admin` убирается. Список опросов, который сейчас
  строится без фильтра (`select(Poll)...`), фильтруется: для каждого
  встретившегося `chat_id` вызывается `is_chat_admin` один раз (локальный
  кэш `dict[int, bool]` на время обработки команды, по аналогии с
  `chat_cache` в `checkme.py`), в список попадают только опросы чатов, где
  результат `True`. Если после фильтра список пуст — тот же текст, что и для
  «опросов нет», без уточнения, что где-то опросы всё же существуют (чтобы не
  палить факт их существования тем, у кого нет прав).
- **`/copypoll`** (`admin_copy.py`): параметр `admin_id`/`_is_admin` убирается.
  Проверка `is_chat_admin(bot, message.chat.id, user.id)` выполняется в
  `start_copy_poll` (текущий чат — это и есть целевой чат, копия публикуется
  только в него, приватные чаты по-прежнему отклоняются как раньше). Список
  опросов-источников фильтруется тем же способом, что и в `/editpoll`.
- **`/cancel`** (`dialog_control.py`): параметр `admin_id`/`_is_admin`
  убирается полностью, без замены. Проверка не нужна: FSM-состояние в aiogram
  уже привязано к конкретной паре (chat_id, user_id), так что `/cancel`
  физически не может отменить чужой диалог.

## 2. `/stats`

Новый роутер `bot/handlers/stats.py`, регистрируется в `main.py`.

```python
@router.message(Command("stats"))
async def handle_stats(message, bot, session_maker, admin_id, timezone): ...
```

- Если `message.from_user.id == admin_id` (это по-прежнему `ADMIN_ID` из
  `.env` — переменная окружения не переименовывается):
  - `repo.get_chat_poll_stats(session)` возвращает `[(chat_id, last_created_at), ...]`,
    отсортированные по дате последнего опроса (убывание).
  - Для каждого `chat_id` название группы резолвится через `bot.get_chat`;
    при ошибке (бот уже не в группе) — вместо тайтла показывается
    `"группа {chat_id} (бот больше не состоит в ней)"`, без прерывания всего
    ответа (тот же толерантный паттерн, что в `checkme.py::_build_lines`).
  - Формат строки: `«{название}» — последний опрос: {дата с годом}`.
  - Если групп нет — отдельный текст `"Бот пока не используется ни в одной группе."`.
- Иначе (любой другой пользователь) — фиксированный текст с кратким описанием
  бота и списком команд:

```
Этот бот помогает организовывать опросы по датам в группах.

Доступные команды:
/newpoll — создать новый опрос
/editpoll — изменить опрос (текст/дату варианта, добавить вариант, порядок, название)
/deletepoll — удалить опрос полностью
/copypoll — скопировать существующий опрос в текущий чат
/checkme — посмотреть, на какие предстоящие игры вы записаны
/cancel — отменить текущий диалог с ботом

Управление опросами (/newpoll, /editpoll, /deletepoll, /copypoll) доступно
только администраторам группы. Чтобы бот мог публиковать и обновлять опросы,
добавьте его в группу и выдайте права администратора.
```

Формат даты с годом — новый небольшой хелпер в `date_utils.py`
(`format_date_ru` года не показывает, а `/stats` может показывать даты из
прошлых лет), например `format_date_ru_with_year(d) -> "23 августа 2026"`.

## 3. Данные

Отдельной таблицы «в каких чатах используется бот» не существует и не
заводится — единственный источник данных: таблица `polls` (`chat_id`,
`created_at`). Новая функция в `repo.py`:

```python
async def get_chat_poll_stats(session: AsyncSession) -> list[tuple[int, dt.datetime]]:
    result = await session.execute(
        select(Poll.chat_id, func.max(Poll.created_at))
        .group_by(Poll.chat_id)
        .order_by(func.max(Poll.created_at).desc())
    )
    return list(result.all())
```

**Известное ограничение**: если из чата через `/deletepoll` удалены вообще
все опросы (жёсткое удаление, не soft-delete), этот чат перестанет
попадать в `/stats`, даже если бот там всё ещё состоит. Отдельную таблицу
чатов ради этого не заводим — сценарий редкий, а усложнение модели данных
того не стоит.

## 4. Что не меняется

- `ADMIN_ID` / `ADMIN_USERNAME` как переменные окружения — не переименовываются
  (не трогаем деплой на bothost.ru).
- `admin_mention` / уведомление при достижении порога голосов — работает как
  раньше, никак не связано с правами на управление опросами.
- Голосование, `/checkme`, напоминания, пороговая логика — без изменений.
- Шаги подключения бота (добавить в группу, выдать права администратора) —
  без изменений.
