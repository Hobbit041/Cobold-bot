# Botopros — Telegram-бот для голосования по датам

## Локальный запуск

```bash
python -m venv .venv
source .venv/Scripts/activate   # Windows Git Bash
pip install -r requirements-dev.txt
cp .env.example .env            # заполните BOT_TOKEN, ADMIN_ID, ADMIN_USERNAME
python -m pytest -v
python -m bot.main
```

## Деплой на VPS (systemd)

```bash
sudo mkdir -p /opt/botopros
sudo chown $USER:$USER /opt/botopros
git clone <repo-url> /opt/botopros
cd /opt/botopros
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env   # заполните реальными значениями

sudo cp deploy/botopros.service /etc/systemd/system/botopros.service
sudo systemctl daemon-reload
sudo systemctl enable --now botopros
sudo journalctl -u botopros -f   # смотреть логи
```

> Состояние диалогов `/newpoll`/`/editpoll` хранится только в памяти процесса
> (`MemoryStorage`). Перезапуск бота (`systemctl restart botopros`, в том
> числе автоматический через `Restart=on-failure`) молча сбрасывает
> незавершённый диалог администратора — если это произошло посреди
> создания/редактирования опроса, диалог нужно начать заново.

## Команды бота (только для администратора)

- `/newpoll` — создать опрос: название → варианты (`Текст | ДД.ММ.ГГГГ`, вместо `|` подойдёт `/` или `\`) → `/done` → chat id или пересылка сообщения из чата
- `/editpoll` — изменить/удалить вариант существующего опроса

## Ручная проверка перед продакшеном

Эти сценарии нельзя автоматизировать без реального Telegram-бота, реального
токена от BotFather и нескольких живых аккаунтов, поэтому перед тем как
считать бота готовым к продакшену, человек должен вручную прогнать их в
тестовой группе (не в проде):

1. **Создание опроса.** В личных сообщениях с ботом выполните `/newpoll`,
   добавьте 2 варианта с датами, отправьте `/done`, затем укажите chat id
   тестовой группы. Ожидается: в тестовой группе появляется сообщение опроса
   с 2 кнопками вариантов.

2. **Голосование и порог в 4 человека.** С 4 разных аккаунтов проголосуйте
   за один и тот же вариант в течение нескольких секунд друг от друга.
   Ожидается: подпись на кнопке обновляется счётчиком после каждого голоса;
   после последнего голоса подождите 15 минут — должно появиться сообщение
   «проголосовало 4 человека» с упоминанием администратора.

3. **Отмена голоса в течение окна ожидания.** В пределах тех же 15 минут
   (до того как сработает сообщение из пункта 2) один из 4 аккаунтов
   отменяет свой голос. Ожидается: сообщение «4 человека» для этого цикла
   не отправляется вообще.

4. **Падение ниже порога после подтверждения.** После того как сообщение
   «4 человека» уже было отправлено, отмените голоса так, чтобы количество
   упало ниже 4. Ожидается: сразу же приходит сообщение о том, что
   «снова меньше 4х человек».

5. **Редактирование текста варианта.** Выполните `/editpoll`, выберите
   опрос, затем вариант, за который уже есть голоса, выберите `text` и
   отправьте новый текст. Ожидается: сообщение опроса в чате обновляется,
   а проголосовавшим приходит уведомление с упоминанием.

6. **Удаление варианта.** Выполните `/editpoll`, выберите вариант с
   существующими голосами и выберите `delete`. Ожидается: вариант исчезает
   из сообщения опроса, проголосовавшие получают уведомление, а любой
   отложенный 15-минутный таймер для этого варианта отменяется (никакое
   сообщение не приходит спустя 15 минут).

7. **Ежедневное напоминание.** Создайте вариант с датой на завтра, доведите
   его до 4 подтверждённых голосов и дождитесь 19:00 по Europe/Moscow (либо
   временно уменьшите `REMINDER_TIME` в `.env` для теста и перезапустите
   бота). Ожидается: приходит одно сообщение-напоминание со списком
   участников, и оно не повторяется в последующие дни.

> Этот раздел описывает чек-лист для человека-тестировщика. Он не был
> выполнен в автоматизированной среде разработки — здесь нет реального
> токена бота и живого Telegram-чата, поэтому перед тем как считать бота
> готовым к продакшену, эти 7 сценариев должен вручную прогнать человек с
> настоящим ботом.
